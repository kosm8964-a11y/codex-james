## 1. 你的核心目标（已整理）

系统需要同时满足：

1. **电脑端可用**（包括 Windows 浏览器）
2. **手机端网页可用**（响应式 H5）
3. 部署在**阿里云服务器**
4. 模块间数据**自动联动**，避免重复录入
5. 订单输入时支持**包/吨双单位自动换算**
6. 每个订单详情可**导出 PDF**（作为购销合同发送客户）
7. 财务模块支持**收款 + 付款（收支管理）+ 账户管理**

## 2. 总体技术方案（满足跨平台 + 阿里云部署）

### 2.1 终端形态

- **统一采用 Web 架构（B/S）**：
  - 管理端：PC 浏览器（Chrome/Edge，Windows 可直接访问）
  - 移动端：手机浏览器访问同一系统（响应式页面）
- 这样你只维护一套后端服务，前端一套代码即可覆盖多个终端。

### 2.2 推荐技术栈

- 前端：Vue 3 + TypeScript + Element Plus（PC）+ 响应式布局（Mobile）
- 后端：Java Spring Boot（或 NestJS/FastAPI，三选一）
- 数据库：MySQL 8.0
- 缓存：Redis
- 文件：阿里云 OSS（合同、回单、发票附件）
- PDF 生成：wkhtmltopdf / Puppeteer / iText（任选其一）

### 2.3 阿里云部署建议

- ECS（2C4G 起步）+ Docker + Nginx
- MySQL（RDS 优先）+ Redis（云 Redis）
- 域名 + HTTPS（SSL 证书）
- 自动备份：数据库每日备份、OSS 生命周期归档

## 3. 模块联动（你最关心的部分）

### 3.1 订单、发货、财务联动规则

#### 规则 A：在订单模块填写“发货/收款相关信息”后自动同步

- 订单字段分三类：
  1. 订单主数据：客户、产品、数量、单价、金额
  2. 发货数据：计划发货日、仓库、承运商、运单号、已发数量
  3. 财务数据：应收金额、已收金额、收款方式、收款账户、收款时间、开票状态

- **同步机制**：
  - 新建订单：自动生成“发货待处理记录”“财务应收记录”
  - 修改订单：按版本更新关联记录并写审计日志
  - 取消订单：自动将发货单/应收单标记为作废或关闭

#### 规则 B：状态驱动数据一致性

- 订单状态 `待付款 -> 可发货`：财务放行后才允许出库
- 发货状态 `已发货`：自动回写订单“已发数量/发货时间”
- 签收状态 `已签收`：自动触发财务“应收转到期”
- 收款完成：自动更新订单为“已回款（或部分回款）”

### 3.2 订单与产品信息联动（自动带出和自动计算）

你提到的场景：输入“A 客户 + 产品一”后自动计算金额，按以下规则实现。

#### 规则 C：自动带出产品与客户价格

在订单行选择 `客户 + 产品` 后，系统自动读取：

- 产品主数据：
  - SKU、产品名、单位（包/吨）、换算关系（每吨多少包）
  - 税率、默认仓库
- 价格策略：
  - 客户专属价（优先）
  - 客户等级价（次优先）
  - 标准销售价（兜底）

#### 规则 D：自动计算金额

- 行金额公式：`行金额 = 计价数量 × 含税单价`
- 订单总金额：`订单总金额 = Σ行金额 - 优惠 + 运费`
- 页面实时计算，保存前后端二次校验，防止篡改。

---

### 3.3 包 / 吨双单位自动换算（你提的关键需求）

#### 数据字段设计（产品信息管理）

每个产品维护：

- `pack_to_ton_ratio`：每吨对应包数（例如 25 包 = 1 吨，则 ratio=25）
- `min_pack_qty`：最小起订包数（可选）
- `allow_decimal_ton`：吨数是否允许小数

#### 换算规则

假设 ratio=25（即 25 包 = 1 吨）：

- 输入包数时：`吨数 = 包数 / 25`
- 输入吨数时：`包数 = 吨数 × 25`

#### 页面交互规则

- 用户可选择输入主单位（包或吨）
- 输入主单位后，副单位自动回填
- 若换算后出现小数包数：
  - 默认提示“不允许非整数包数”并阻止提交
  - 若产品允许散包，可在产品配置中开启

#### 示例

- 输入 `25 包` -> 自动换算 `1 吨`
- 输入 `1 吨` -> 自动换算 `25 包`

### 3.4 订单详情导出 PDF（购销合同）

#### 规则 E：订单详情页一键导出 PDF

在“订单详情”页面增加按钮：`导出订单（PDF）`。

PDF 内容建议包含：

1. 订单基础信息：订单号、日期、客户名称、销售员
2. 产品明细：产品名、规格、数量（包/吨）、单价、金额
3. 金额汇总：合计、税额、应收金额
4. 打款信息：客户应打款账户（收款账户名、开户行、账号）
5. 回款信息：已收金额、未收金额、收款记录
6. 双方确认区：甲方/乙方签章位、备注条款

> 该 PDF 作为“对外订单确认单/购销合同”发送给客户。

#### 规则 F：PDF 与财务数据实时关联

- PDF 中的“打款账户”来源于财务账户管理（只允许启用账户）
- PDF 中的“回款状态”实时读取财务应收/收款记录
- 若财务数据变化，重新导出时自动反映最新金额与状态

---

### 3.5 财务管理扩展为“收支管理 + 账户管理”

#### 规则 G：账户管理（非常关键）

财务页面需维护两类账户：

1. **我方收款账户**（客户打款到哪里）
   - 账户名称
   - 开户行
   - 银行账号
   - 账户类型（对公/对私）
   - 启用状态（启用/停用）
2. **供应商收款账户**（我方向供应商付款）
   - 供应商名称
   - 开户行
   - 银行账号
   - 账户户名
   - 默认账户标记

#### 规则 H：收支管理

- **收入（收款）**：客户回款登记，关联订单/应收单
- **支出（付款）**：向供应商付款登记，关联采购单/应付单（若采购模块后续上线）
- 每笔收支都要有：金额、账户、日期、凭证附件、操作人
- 自动形成资金流水台账，可按日期/客户/供应商筛选

#### 规则 I：财务闭环

- 收款记录 -> 更新订单回款状态与应收余额
- 付款记录 -> 更新应付状态与供应商往来账
- 收支报表 -> 汇总“收入、支出、净现金流”

## 4. 关键业务流程（按你的操作习惯）

1. 销售新建订单，选择客户与产品。
2. 系统自动带出价格、换算关系、税率，自动计算金额。
3. 你在订单页录入发货计划与财务信息（录一次，多处联动）。
4. 系统自动同步生成发货记录、应收记录。
5. 订单详情可一键导出 PDF，发给客户作为确认合同。
6. 客户按 PDF 指定账户打款，财务登记收款并回写订单。
7. 你向供应商付款后登记付款记录，形成完整收支台账。

## 6. API 设计重点（保证联动）

- `POST /orders`：创建订单（同时生成发货/应收）
- `PUT /orders/{id}`：修改订单（同步更新关联单据）
- `GET /pricing/resolve?customerId=&productId=`：解析客户产品单价
- `POST /unit/convert`：按产品规则换算包/吨
- `POST /orders/{id}/export-pdf`：导出订单 PDF
- `GET /finance/accounts/active`：查询可用收款账户
- `POST /finance/receipts`：登记收款并更新订单状态
- `POST /finance/payments`：登记供应商付款并更新应付状态
- `GET /finance/cash-ledger`：查询收支流水

## 7. 权限与审计（避免后期对账扯皮）

- 销售可建单改单，但关键字段（单价、金额）改动需审批
- 财务可维护账户、登记收付款、管理发票
- 仓库可改发货与物流状态，不能改价格
- 所有关键动作写入 `audit_logs`（谁在何时改了什么）
